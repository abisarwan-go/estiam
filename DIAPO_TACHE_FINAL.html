Business context

Contexte métier

  • PyMart = enseigne retail multi-catégories
  • Le personnel exporte des fichiers texte depuis le POS
  • Ces exports sont sales : champs manquants, séparateurs, casse, nombres/dates invalides
  • Les managers veulent des rapports daily / monthly reproductibles et archivables
Objectif

Ce qu’il faut construire

Application Python production-ready pour les opérations quotidiennes.

1. Importer

Produits, clients, commandes depuis fichiers texte

2. Valider / nettoyer

Données sales → représentation interne propre

3. Traiter

Créer / lister des commandes

4. Rapporter

Rapports datés à la demande / planifiés

5. Robustesse

Messages clairs, pas de crash

6. Archive

Écriture disque, dossiers datés

Functional requirements · CLI

Entrée : module -m ou script. Minimum exigé :

ExigenceChez PyMart

Data importing + string/list

Import & nettoyage des données

Fichiers d’entrée

  • Texte CSV-like (séparateur |)
  • ≥ 1 fichier produits
  • ≥ 1 fichier clients
  • ≥ 1 fichier commandes / lignes

Techniques demandées

  • split, strip, join, replace
  • casse : upper / title / lower
  • filtrage lignes vides / commentaires
  • conversion int / float sécurisée

Cas gérés : espaces, colonnes manquantes, nombres invalides, quantités négatives, IDs mal formés.

Exception handling

Exceptions custom

  • try / except / else / finally pour I/O et parsing
  • ≥ 2 classes d’exception custom (exigé)
  • Messages actionnables : contexte file= + line=

Product

Polymorphisme : chaque classe redéfinit describe()

Custom modules / packages

Package multi-modules

Pas un seul script : séparation des préoccupations.

pymart/
├── cli.py              # argparse / commandes
├── models/             # Product, Customer, Order, sous-classes
├── io/parsers.py       # lecture + nettoyage (stream)
├── services/store.py   # import, stock, commandes, JSON
├── reports/writers.py  # daily / monthly / stock
└── exceptions.py       # erreurs métier
